# subset

Spatially subset a **NISAR L1 RSLC** to an area of interest and save the result as a smaller
RSLC with the full NISAR HDF5 layout. The subset can be used as input to **ISCE3** and the
NISAR workflows just like a full-size product.

```bash
subset-rslc NISAR_L1_PR_RSLC_004_122_D_067_4005_DHDH_A_20251106T160541_20251106T160622_X05009_N_F_J_001 \
    --aoi "POLYGON ((-147.9 64.8, -147.6 64.8, -147.6 64.9, -147.9 64.9, -147.9 64.8))" \
    -o my_subset.h5
```

```python
from nisar_subset import subset_rslc

result = subset_rslc(granule_id_or_path, aoi_wkt, "my_subset.h5")
```

A walkthrough is in [`notebooks/subset_rslc_example.ipynb`](notebooks/subset_rslc_example.ipynb).

## Install

```bash
pip install "nisar-subset[remote] @ git+https://github.com/Alex-Lewandowski/subset"
# or, from a clone:
pip install -e ".[remote,notebook]"
```

Core dependencies are `h5py`, `numpy`, `scipy`, `shapely` and `pyproj`. The `remote` extra
adds `earthaccess` for granule IDs. ISCE3 is **not** required; the subsetter only uses the
product's own geolocation grid.

## Input

* **Source**: a local RSLC path, an open `h5py.File`, or a **granule ID**.
  * A granule ID is looked up in NASA CMR (`NISAR_L1_RSLC_V1`, `..._PROVISIONAL_V1`,
    `..._BETA_V1`) and **streamed** over HTTPS by default. Only the HDF5 chunks that overlap
    the AOI are read, so the full ~30 GB file is not downloaded.
  * Use `--download` / `mode="download"` to fetch the whole file first.
  * Use `--s3` / `access="direct"` to read directly from S3 when running in AWS us-west-2.
  * Earthdata Login credentials come from `~/.netrc`, from `EARTHDATA_USERNAME` /
    `EARTHDATA_PASSWORD`, or from an interactive prompt.
* **AOI**: any of the following. Use `--aoi-epsg` for other CRSs.
  * WKT
  * GeoJSON (string, dict or `.geojson` file)
  * a `.wkt` file
  * a `(min_x, min_y, max_x, max_y)` box (`--bbox`)
  * a shapely geometry
  * an explicit line/sample window (`--rows` / `--cols`)

Other options:

* `--pols HH HV` / `--frequencies A`: keep only those layers.
* `--pad N`: add a margin of N lines/samples.
* `--heights 0 3000`: see below.
* `--no-crop-metadata`: keep the metadata LUTs full-size.
* `--lut-margin N`: number of LUT nodes kept around the window (default 3).

## What the output contains

The subset has every group, dataset and attribute of the input, in the same order. It keeps
the same datatypes (including NISAR `complex32`), chunking, compression filters, fill values,
file-space settings (paged aggregation) and HDF5 dimension scales. What changes:

| Where | Change |
|---|---|
| `swaths/zeroDopplerTime`, `swaths/frequency*/slantRange` | cut to the window |
| `swaths/frequency*/{HH,HV,...}` | cut to the window; statistics attributes (`min_real_value`, `sample_stddev_imag`, ...) recomputed |
| `swaths/frequency*/validSamplesSubSwath*` | rows cut, column indices shifted into the new grid and clipped |
| `swaths/frequency*/sceneCenterAlongTrackSpacing`, `sceneCenterGroundRangeSpacing` | re-evaluated at the centre of the subset |
| `metadata/geolocationGrid`, `metadata/calibrationInformation/**`, `metadata/processingInformation/parameters/**` | every LUT on its own `zeroDopplerTime`/`slantRange` axes is cropped to the window plus a margin of nodes, so it still covers the whole subset |
| `metadata/orbit`, `metadata/attitude`, everything else | unchanged |
| `identification/zeroDopplerStartTime`, `zeroDopplerEndTime` | first/last line of the subset (same string format) |
| `identification/boundingPolygon` | footprint of the subset |
| `identification/isFullFrame` | `"False"`; `frameCoveragePercentage` scaled by the area ratio |
| `listOfFrequencies` / `listOfPolarizations` | updated if layers were dropped |
| root attribute `history` | records the source granule and window |

Sampling (`zeroDopplerTimeSpacing`, `slantRangeSpacing`) and the radar parameters do not change,
so the subset's ISCE3 radar grid is exactly the full grid offset to the window.

### Terrain height

A ground point's position in the radar image depends on its height. By default the AOI is
placed using the mean `referenceTerrainHeight` the processor used over the AOI. In steep
terrain, pass the expected height range (`--heights 200 2500`). The window then covers the AOI
at every height in that range.

## Validation

`pytest` runs 26 tests that don't need ISCE3. They use
`tests/data/envisat_rslc_fixture.h5`, a real Envisat scene in NISAR RSLC format whose
geolocation grid was generated by ISCE3's own writer (see `tests/make_fixture.py` and
`tests/data/NOTICE`).

Two scripts use ISCE3 (`conda install -c conda-forge isce3`) to check a subset against its
input:

```bash
python tests/validate_with_isce3.py FULL.h5 SUBSET.h5 --aoi "POLYGON ((...))"
python tests/geocode_compare_isce3.py FULL.h5 SUBSET.h5
```

The first opens both products with ISCE3's NISAR reader and checks:

* the subset radar grid equals `full_grid.offset_and_resize(...)`;
* the image samples are identical;
* the Doppler, noise and calibration LUTs cover the subset grid and match the full product;
* the orbit is identical and the start time is correct;
* ISCE3 `geo2rdr` puts every AOI vertex inside the subset.

The second geocodes both with `isce3.geocode.geocode_slc`. The subset's output is
bit-identical to ISCE3 geocoding the same block of the full product.

These checks pass on the fixture and on ISCE3's `winnipeg.h5` (dual frequency),
`REE_RSLC_out17.h5` and `envisat.h5` test products. The AOI windows match ISCE3 `geo2rdr`
extents to within one pixel.

## Notes

* The AOI must overlap the scene. If part of it is outside, the subset is clipped and a warning
  is raised.
* AOI placement works for scenes that cross the antimeridian. The subset's `boundingPolygon` is
  written in −180…180° longitude, so a subset that itself straddles 180° gets a polygon that
  wraps around.
